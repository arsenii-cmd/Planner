# Planner

[English](README.md) · **Русский**

Календарь, задачи на день и быстрые заметки, которые синхронизируются между Linux-компьютером и
Android-телефоном по локальной сети — без облачного аккаунта и без чужих серверов.
Половина на компьютере — маленький демон на Python поверх SQLite; половина на телефоне —
приложение на Flutter, которое подключается сканированием QR-кода.

Всё хранится на ваших собственных устройствах: телефон обращается к демону напрямую по HTTPS
в локальной сети и закрепляет его самоподписанный сертификат из QR-кода. Ничего не покидает сеть.

## Что здесь есть

| Путь | Что это |
| --- | --- |
| `server/plannerd.py` | Демон синхронизации: JSON API, хранение в SQLite, анонс по mDNS, уведомления-напоминания |
| `server/quickparse.py` | Разбор свободного русского текста: `завтра 18:00 занятие` → событие завтра в 18:00 |
| `server/planner-add` | Окно быстрого добавления для плавающего терминала (на `SUPER+P`) |
| `server/plannerd.service` | Пользовательский юнит systemd для демона |
| `app/` | Приложение на Flutter: календарь, задачи, заметки, фоновая синхронизация, виджет ([app/README.md](app/README.md)) |

## Сервер

Нужен Python 3.11+ и больше ничего; `zeroconf` необязателен и только добавляет обнаружение
по mDNS, `qrencode` только рисует QR-код для подключения в терминале.

```sh
install -Dm755 server/plannerd.py ~/.local/bin/plannerd
install -Dm644 server/quickparse.py ~/.local/bin/quickparse.py
install -Dm644 server/plannerd.service ~/.config/systemd/user/plannerd.service
systemctl --user enable --now plannerd
```

Данные лежат в `~/.local/share/planner/planner.db`; настройки, токен доступа и сертификат TLS —
в `~/.config/planner/`. Токен создаётся при первом запуске — его никогда нет в репозитории, а
`plannerd reset-token` отключает все подключённые телефоны.

```sh
plannerd pair             # QR-код + адрес, порт и токен текстом
plannerd add "завтра 18:00 занятие // взять тетрадь"
plannerd reset-token      # отключить всё
```

Демон слушает TCP 47210 (HTTPS, нужен токен) для локальной сети и `127.0.0.1:47211` (обычный
HTTP, без токена) для виджетов на этом компьютере. Если у вас файрвол, откройте 47210.

## Режим сервера (база на сервере)

Чтобы база жила на всегда включённом сервере, а не на компьютере, запустите plannerd за
обратным прокси с TLS и настоящим сертификатом:

```sh
install -Dm644 server/plannerd.py server/quickparse.py -t /opt/planner/
install -Dm644 server/plannerd-server.service /etc/systemd/system/plannerd-server.service
systemctl enable --now plannerd-server
```

Тогда демон слушает `127.0.0.1:47212` по обычному HTTP и требует токен от каждого клиента,
включая локальные (прокси подключается оттуда же). Ни mDNS, ни уведомлений на рабочем столе.
Он хранит только зашифрованные сквозным шифрованием записи: быстрое добавление и любая запись
без зашифрованного `blob` отклоняются с кодом 400, так что на сервер ничего не попадает в
открытом виде. Направьте на него прокси, например для Caddy:

```
planner.example.com {
    reverse_proxy /api/* 127.0.0.1:47212
}
```

Подключите телефон по публичному адресу:

```sh
XDG_CONFIG_HOME=/var/lib/planner/config python3 /opt/planner/plannerd.py pair --url https://planner.example.com
```

Тогда в QR-коде `{"planner":2,"name":…,"url":"https://…","token":…}` — `url` вместо
`hosts`/`port`/`fp`. Сертификат проверяется обычным способом (публичный центр
сертификации), закреплять нечего. Перенос существующей базы: остановите оба демона,
скопируйте `planner.db` в `/var/lib/planner/`, запустите сервер, подключите телефон заново.

## Приложение

```sh
cd app
flutter pub get
flutter build apk --release
```

Затем откройте приложение, нажмите «подключить» и отсканируйте то, что печатает `plannerd pair`.
Приложение снова находит демон по mDNS, когда меняется адрес ноутбука, синхронизируется в фоне,
показывает локальные уведомления для событий с напоминанием и может вывести список на сегодня
виджетом на главный экран.

## Копия без рабочего стола (local-only)

Всегда включённая машина без рабочего стола (например, с голосовым помощником) может держать
свою расшифрованную копию Planner, подключённого к облаку, и отдавать её только программам на
этой же машине:

```bash
plannerd serve --local-only
```

Она слушает только `127.0.0.1:47211`: ни порта в локальную сеть, ни mDNS, ни уведомлений
(ежедневный перенос незаконченных задач всё равно работает). Дайте ей раздел `cloud` из
настроек компьютера (`url`, `token`, `key`) с `"seq": 0`, `"enabled": true` и своим `"device"`
(например, `"homebox"`), чтобы её изменения подписывались её именем, а не `desktop`.
`GET /api/items?q=текст` ищет записи по заголовку или тексту без учёта регистра.

## Синтаксис быстрого добавления

`quickparse.py` превращает одну строку по-русски в запись. Если есть время — это событие,
иначе — задача на указанный день.

```
завтра 18:00 занятие               событие завтра в 18:00
в пятницу с 10 до 11:30 созвон     событие в ближайшую пятницу, 10:00–11:30
25.09 в 9 стоматолог               событие 25 сентября в 09:00
18:00 2 недели занятие             еженедельная серия из 2
купить хлеб                        задача на день по умолчанию
18:00 занятие // взять тетрадь     всё после // становится описанием
```

## Модель синхронизации

У каждой записи есть `updated_at` в миллисекундах и id устройства, которое её записало.
Стороны обмениваются всем, что новее последнего увиденного номера; при конфликте побеждает
более поздняя запись, при равенстве — по id устройства. Удаления — это надгробия
(tombstones), поэтому они расходятся так же, как любые другие изменения.
